# Generic server menus: client 0.15.1

The 0.15.0 bridge recognized only rows starting with a bare number and a dot/parenthesis. Buy prints that format (`1. Vehicles`). Formation uses explicit commands (`/1 Move`), including `Formations:` prefixes. UnitBalance uses rich-text `[BAL]` prefixes and several numbered options in one line (`1. Sol  2. Centauri`). They share a chat transport, but do not share a text layout. The former client also invented `/back` and `/0` for any numbered reply, which does not match every mod's navigation contract.

0.15.1 uses one bounded generic parser for all server replies. It supports bare numbers, explicit slash/dot/exclamation numeric commands, rich-text and sender prefixes, multiple rows per message and multiple choices per row. Labels and values are preserved, active menu choices appear before ordinary command references, and their server order is retained. Back/Close entries come from explicit reply advertisements; toggle-close commands also require confirmed registry membership. No per-mod catalog or gameplay changes were added.

An active menu's origin and access metadata now take priority over unrelated aliases. Numeric choices can carry user-entered arguments (for example `/2 1.5`) while retaining the original administrator restriction and captured reply routing. Vote commands retain exact matching. Correlation, bounds, expiry and native fallback behavior remain. Error replies cannot create menu choices. The existing prepare-then-SEND interaction is retained.

This fixes common menu text compatibility, not every possible custom protocol. A numeric statistic must not be treated as a menu action; unknown syntax stays visible as feedback and can still be entered manually. Some mods deliberately reject opening while another mod owns a chat menu. Formation's MenuIsolation and Buy/UnitBalance state checks are examples. They need an explicit shared ownership/cancel API for reliable automatic switching; the client does not inspect or mutate those mods' private states or silently execute guessed close commands. Asynchronous output outside synchronous reply capture is still native.

Source baseline: installed client 0.15.0, backed up under Backups/ModUI-generic-menus-20261020T170851568Z. The installed server remains 1.1.0 and requires no update for this fix. Live verification should cover Buy root/category, Formation function/formation selection, UnitBalance root/editor/value entry, permissions, and explicit menu close before switching mods. Offline fixtures check representative actual output formats and production receive/routing code; they do not execute gameplay callbacks.

This client patch is prepared, not installed. Existing 0.15.0 release archives remain intact. Its installer can select the new package explicitly with Install-ModUI.ps1 -Side client -ReleaseVersion 0.15.1. Settings and the existing cheats 0.3.1 provider are retained.
