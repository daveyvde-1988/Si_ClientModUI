## 0.8.0 overlays (current)

The Q4/P4/UM/UB protocols stay compatible. UO options carry nonce/channel/team plus two bounded flags (notification routing and optional status). They are authenticated against the native remote peer and current subscription, renewed every five seconds, and expire after 12 seconds. They do not confer admin authority. Local geometry and hidden parameter choices never leave the client.

US parameter packets include nonce, monotonic sequence, chunk index/count and full-replacement/delta flag. Base64 rows contain bounded ID/mod/label/value strings; <=128 rows and <=1800-character bodies. Clients assemble a whole sequence before replacing/merging, reject duplicate IDs/inconsistent counts and stale contexts, and mark values stale after 15 seconds. Initial/provider-set changes and about-30-second recovery frames replace; intervening frames carry changed values only, with small about-10-second liveness frames. Only expanded status/picker subscribes. A player's scoped stats and admin-only providers are evaluated on the server; no arbitrary reflection names are accepted from clients.

UN notices are recipient-scoped, nonce-bound bounded text, on the same reliable native transport. Reviewed AdminMod chat delivery and registered-mod native server broadcasts can be redirected. Suppress an original only after accepted UN send. Team/private recipients come from the original delivery loop. The native-send scope is thread-local, restored in a Harmony finalizer, with a recursion guard on replacement delivery. Ordinary player chat and vanilla server messages with no registered-mod origin are retained. Custom transports not using either reviewed path are retained. Errors, unavailable/changed-hash adapters, expired subscription leases, >1100 UTF-8-byte messages and >60 notices/second use native chat. The client keeps 200 notices in memory and redacts webhook URLs before displaying them.

Independent sidebar P4 requests retain role/team/nonce/revision checks, partial-list assembly, request retry/deduplication and known fingerprints. Main and sidebar control requests share the client cooldown and are serialized; the sidebar reuses the main commander page when available. Catalog data never survives nonce/team/role changes. The on-screen preference is retained independently.

Existing HUD upload counters include US/UN packets sent by the companion; they still exclude native/Steam framing and retransmissions. Normal native chat fallback and other gameplay/mod traffic are not counted as HUD payload. No network measurements or live routing verification were performed during implementation.

# HUD and mod-menu transport 0.4.0

The companion uses the authenticated native game connection, packet byte 126 and exact marker SiSquadHUD/1. It refuses activation if the native enum claims 126. Existing packet peeking, reader-position restoration, remote-peer/channel/team validation and per-packet limits remain: body <=1800 ASCII characters, native packet <=2100 bytes. Other traffic proceeds unchanged. This is a private bridge, not an official mod network API.

## Status and request scope

Q2 subscriptions and S2 status retain the prior schemas, including nullable authoritative score/credits. Old Q clients still receive S status. Non-mod clients receive no unsolicited HUD traffic. Status expires on the client after fifteen seconds and is scoped to server/player/nonce/team/sequence; scene/observed-round changes clear context. Server subscriptions expire after twenty seconds without a valid keepalive.

P reads and A actions retain nonce, player channel, team, commander role, request ID, function and page fields. A adds action/option/revision. Current clients send page **2048** as a full-catalog sentinel. The native Formation API's internal pages are assembled server-side; they are never exposed as UI pages. Other functions build a full authoritative catalog directly. Old page requests remain supported.

Functions: follow/move/attack for FPS, commander for commander, and buy/ranks/help-fps/help-commander/help-admin/admin for either role. Formation actions are select, lock and disband. Buy accepts purchase. Admin accepts enable/disable. Info tables accept no actions. IDs/nonces are 32 hex characters; revisions are 64 hex. No SteamID or command text supplied by the client determines the actor or executable handler.

## Complete catalog snapshots

G responses contain the prior scope/state metadata plus an authenticated Generic-admin flag and row records. Header fields: tag, nonce, team, commander, requestId, function, chunkIndex, chunkCount, selected, locked, enabled, available, leader, revision, base64(message), adminFlag, rows. A row is number:base64(name):base64(description):base64(group):base64(data); rows are comma-separated. Base64 protects framing, not confidentiality.

A snapshot has at most 512 rows and 512 chunks; each chunk has at most six rows and is packed adaptively under the existing packet budget. Names/groups are capped at 96 UTF-8 bytes, descriptions/data at 400 bytes each, and messages at 120 bytes in providers. Buy group is the production facility. Rank data contains tier/score/cap/bonus/allowed/seats separated by | inside the encoded field. Admin data contains observed state and whether its live adapter is available. No private config file is sent wholesale.

The client collects all chunks for one pending request ID, requiring matching server/nonce/team/role/function, revision, chunk count and state flags. It bounds aggregate row count and rejects duplicate row numbers. Rows become actionable only after a complete snapshot. Partial snapshots are discarded on timeout/context changes. Read retry occurs once after two seconds with the same ID; after eight seconds an incomplete transfer is reported without assuming success. Informational lists refresh every thirty seconds, Formation every ten and Admin every five; confirmation suppresses Buy auto-refresh.

## Actions and permissions

Packet parsing queues one pending control per authenticated subscription, at least 0.3 seconds apart. Main-thread OnUpdate revalidates connection/channel/team/role/nonce before applying. The last 32 action IDs cache their entire bounded reply array so retries do not reapply purchases or switches. Round/scene boundaries clear subscriptions and action history. Gameplay handlers run after native packet dispatch unwinds.

Formation keeps its existing player-scoped API, role/leader checks, catalog/round revision and cleanup. Native selection still disables all personal FPS formations. Buy choices are reconstructed from current KoH faction dictionaries and prices. The adapter checks active mode/round, admin-only and Unit Balance editor gates, then invokes KoH's original TryPurchase for credit, cooldown, Shrimp unlock, prefab, spawn and location checks. Native KoH chat reports its detailed result. No second economy/spawn path is implemented.

Admin reads/actions require AdminMod Generic power on the server; the client flag only controls presentation. A new request cannot enable a mod through a hidden button. Catalog revisions include observed state, so stale or concurrent toggle requests are rejected. Rows map to a server-built allowlist, never arbitrary fields, reflection targets or commands from the client. Formation uses RequestGlobalEnabled(bool). KoH, Logistics, Crab Cannon and Heavy Teleporter call their inspected explicit on/off handlers. Their existing cleanup/save behavior is retained. Other loaded mods are reported as Loaded / No live switch; nothing is unloaded or generically unpatched.

Private adapter hashes are pinned in AdminControls.cs / MenuCatalog.cs. Reviewed KoH hash: 5377B71A034E065DF76D5A3F595DE733DAF24D9A875DEF9D0C092BCCAAABF8BC. Reviewed current Logistics hash: 9BA61FE9ACF1E9A34C6773BC9DE9C4D0B7E23CE44C1E99E48D34F27741EFE20E. Hash/signature mismatches disable those controls. The manifest records installed provider hashes for provenance.

Ranks reads the loaded engine configuration without observing score for promotion or mutating state. Traitor rules are based on the inspected rank engine: third counted teamkill enters the hidden faction tier, counted strikes obey configured cooldown, promotions remain locked until round reset, AI recruitment is unavailable and source-specific reward penalties apply. Help reads active command registries plus reviewed intercepted/contextual command variants, excluding numeric/back/close navigation rows. Tables are reference text, never executable command buttons.

## Unit Balance protocol - 0.6.0

New clients subscribe with Q3; the server retains Q/Q2 support for older HUD features. UM carries nonce, monotonic menu-state sequence, four tab bits (Formation/Buy/Ranks/Unit Balance) and authenticated Generic-admin presentation state. This is independent of the selected catalog/menu. Older clients do not get the new balance features or visibility changes.

UB transfers carry nonce, transfer ID, compressed-content SHA-256, zero-based chunk index/count and base64 data. Each data chunk is at most 1050 bytes; limits are 1024 chunks and 2 MiB decompressed JSON. SHA-256 and complete assembly precede JSON use. GZip decompression is bounded. Server outboxes send at most four chunks per subscriber per 50 ms, with a global budget of 32. Only opt-in authenticated subscribers receive snapshots, on subscription/lifecycle reset or changed balance publication; admins also refresh when saved JSON changes. Private settings are omitted through an explicit root allowlist and recursive private-key filtering.

Snapshots include published sanitized configuration, sanitized defaults, a field catalog with paths/types/groups/captured vanilla baselines, reload generation, snapshot serial and opaque edit revision. Generic admins additionally receive sanitized saved JSON for Configure. The public view always reads the published configuration; the admin editor reads saved JSON. Snapshot serials reject older complete data. Native !rebalance is observed by a postfix on the reviewed existing handler; source and DLL remain untouched. The adapter is pinned to Unit Balance SHA-256 23e5f58f3337e081b784d4d940f46ec81451c630c900cc3610fac11f68609c66.

UC contains nonce, request ID, native channel/team/role, fixed operation (stage/save/reload/refresh), edit revision, draft ID and bounded base64 payload (at most 900 UTF-8 bytes). Native remote peer authenticates the actor. Effectful operations execute on OnUpdate after dispatch, rechecking scope and Generic power. Refresh is read-only and available to subscribed ordinary players. UR acknowledges request ID, result and revision. The last 32 balance request IDs/results are deduplicated per subscription; retries reuse IDs.

Stage accepts only numeric/boolean values or removal of fields in the server-built allowlist. Paths are selected by server field ID, never client-supplied filesystem or reflection names. Staged batches are scoped to the subscription/draft/revision, at most 256 fields, with an explicit matching count on Save. A changed disk hash or reload generation rejects the edit revision. The client sends the original edit revision for every batch operation; incomplete batches cannot commit. Close/connection/role/permission/lifecycle changes cancel client staging; server effects require renewed authorization.

Saving re-parses the existing server JObject, patches only allowed fields and preserves other keys. It verifies the original SHA-256 immediately before atomic File.Replace; the replacement and generated backup are hashed afterward. Backups are local server files; no configuration is published merely by staging or saving. Reload uses the native handler, retaining its synchronization and configured Discord behavior. Observed reloads update published data; failed/non-confirmed reloads do not claim new JSON is active. Initial publication is the loaded JSON, explicitly labelled as configuration rather than measured live-object telemetry.

Native Unit Balance enabled=false is not full unhook/unload: independent rules in the reviewed DLL may remain active. The companion does not alter those gameplay patches. Tab visibility follows the observed native flag and existing reviewed Formation/KoH switch states; unsupported mod switches are not invented.
## Native admin menu and conditional catalog protocol - 0.7.0

Q4 advertises current-node admin menus and fingerprinted catalog reads. Q/Q2/Q3 remain supported. New clients get the public balance snapshot regardless of admin status; the saved full JSON is only retained for legacy Q3 admin clients. New admin navigation does not invalidate/re-send the public balance cache. Observed native reloads still publish changed public data to all subscribed clients.

UC operation=menu carries a bounded JSON payload with service=balance|starter, choice and optional value, scoped by the existing authenticated peer/channel/team/role/nonce and a server-issued menu revision. Only Generic admins may invoke it, after packet dispatch on OnUpdate. The server accepts only currently offered row IDs or fixed open/back/refresh/reload actions. It never accepts arbitrary commands, method names or file paths. Menu response JSON has Kind=admin-menu and matching Request ID, Service, Revision, Title, bounded Lines/Rows and confirmation/navigation flags. It uses the same bounded GZip/SHA-256 UB envelope, but the client routes it separately from the public balance cache. The last 32 response arrays deduplicate retries without replaying effects.

Unit Balance uses its reviewed existing OnBalanceCommand/ProcessMenuInput/ShowCurrentMenu handlers. Output capture is limited to its own SendChatToPlayer/SendConsoleToPlayer for the authenticated actor during a synchronous handler call. The UI's native state is temporarily installed in that actor's menu registry, then prior chat/stats state is restored in finally. No persistent UI state is left in the chat registry. Prefixes on reviewed config writers verify a local pre-write backup only during UI execution. Ordinary chat retains the mod's existing behavior. Native confirmations govern effects, including immediate settings and Save+rebalance. Discord configuration rows are disabled; private URLs are redacted from captured output.

Starter Units has no native editor. Its server-built hierarchical menu accesses only sol.json, centauri.json, alien.json, wildlife.json and 4way_cross_spawns.json beneath the known StarterUnits directory. Offered entry indices, loaded unit catalog choices, file/state fingerprints, count bounds, Generic power and confirmation are checked before preserving/patching JSON. A verified backup precedes atomic replacement; new missing files are created without overwriting a competing new file. Native next-round spawning is never invoked by the editor.

P4 reads add Known, a 64-hex canonical catalog fingerprint, to the existing P fields. On a complete matching result, GU returns nonce/team/role/requestId/function/fingerprint only. Otherwise the normal full G chunks are sent. Actions always retain full responses and existing deduplication. Both sides hash the same normalized rows/state, ignoring transport IDs/chunk boundaries. Client caches are scoped to nonce/team/role and never made actionable without matching authoritative context. Poll timing is retained; only unchanged response size is reduced.

Large identical snapshot JSON can reuse compressed bytes across recipients. Server logs scheduled transfer packet/body-byte counts and approximately minute-long totals of successfully accepted HUD sends (all payload types). These application counters exclude native/Steam framing, transport retransmissions, normal gameplay and other mods' own traffic. Full public reports remain once per subscription/lifecycle/reload, not once per admin navigation click.
