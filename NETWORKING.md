# Communication: Si_ClientModUI 0.15.0 / Si_ServerModUI 1.1.0

Singleplayer sends no companion packets. Local providers, user commands and native chat remain available without the addon. The multiplayer header/status reports checking, detected, not detected, offline or transport unavailable; not detected means no validated response. Clicking its menu-header indicator explicitly restarts discovery.

Discovery sends a hello after a server/player/admin identity or scene change, with at most three attempts four seconds apart. Each connection uses a new 32-hex nonce. Opening, arranging and resizing UI sends no requests. No ongoing client catalog polling or heartbeat exists. The server checks registry/configuration/permissions every five seconds and pushes changed catalog diffs. Rechecks and reply timeouts can start a new bounded discovery cycle.

Native packet type 126, marker SiSquadHUD/2, reliable delivery. The protocol is shared with the server project and remains compatible with the friend's backend. Transport disables itself when the game declares the reserved packet type. Custom receive hooks authenticate the current server/actual player peer, validate marker and nonce, and restore reader position for native/other-mod processing. Transfer bodies, counts, concurrent assemblies, stale transfer lifetimes, JSON depth, expanded gzip size and catalog entries are bounded. Malformed diffs do not partially update active metadata.

Server frames are stored under UserData/Si_ModMenu/server-frames using server Steam ID, local Steam ID and channel. They are diff hints only: nothing cached appears as available until a fresh authenticated frame confirms it. Anonymous server Steam IDs may change on restart, causing a fresh full frame rather than a potentially ambiguous name-based cache. Permission changes produce server-side per-player diffs and remove obsolete navigation; client role/admin filtering remains in force. Authorization is always enforced again by the native server dispatcher.

Only text matching confirmed server commands/aliases or currently advertised menu/vote choices uses the proxy. One request is outstanding per client; sequences and exact command text correlate replies. Replies fill the existing feedback view. Numbered lines become explicit navigation entries using the server-supplied prefix, plus back/0 choices; they expire after 60 seconds or a context/command/catalog change. Vote choices expire on vote-end or advertised duration. Server argument choices are ordinary draft entries in the existing command list.

Other explicit SEND/Enter/sidebar submissions retain Player.CurrentPlayer.SendChatMessage, including arbitrary chat and unlisted commands. Provider Invoke callbacks remain owned by the provider. A submitted proxy command is never automatically retried or sent through chat on timeout; it may already have executed. Timeout clears pending navigation and restarts discovery only. Server restart recovery requests a new hello without executing an unrecognized-session command.

The server captures only synchronous Si_AdminMod helper output to the invoking player, with bounded capture. Broadcast, asynchronous and overflow output stays native. Native server-chat feedback routing remains authenticated and optional through the existing notification preference. Structured metadata, caches and learned server feedback are excluded from created-commands.json; only explicit saved/imported/user-sidebar definitions export.

Input isolation, team colors, GUI scaling, transparency, per-team sidebar bindings, settings paths and local provider APIs are retained from 0.14.0. See INTEGRATION_ANALYSIS.md for the exact scope. Native Harmony/Steam transport and live UI verification remain pending; offline harness checks do not establish live interoperability.
